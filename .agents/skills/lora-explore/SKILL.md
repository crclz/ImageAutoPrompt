## lora

lora 可以叠加多个（2-5个），需要不断探索，不断试错。
权重写在 lora 语法里，例如 <lora:xxx:0.9>。探索时使用推荐值（库中 [最高权重: x] 标注）或默认 1.0。
权重范围 0.2 ~ 默认权重。

## 冲突处理

多 lora 叠加时，如果画面变花（结构崩坏、细节混乱、风格打架），一般是 lora 冲突。
- 整体冲突（怀疑 lora 之间普遍互相干扰）：整体降低权重，将所有 lora 的权重一起减小，降低冲突程度。
- 局部冲突（怀疑某个 lora 是主要元凶）：基于历史进行有限推理，soft 降低——怀疑程度高的多降一点，不怎么怀疑的少降一点。不要一刀切，这属于玄学领域，用模糊推理而非精确判断。
- 降权同样遵守 0.2 下限；降到 0.2 仍花则考虑移除该 lora。

## workflow: lora exploration and exploitation

中心思想：从无 lora 或者指定的 lora 开始，从简单到复杂：先尝试少量 lora 组合，逐步复杂化，途中根据用户的反馈，调整 lora 组合。最终得到最优 lora 组合。

### 前置澄清

如果用户未明确以下事项，请向务必向用户显式提问，确认清楚后，才开始流程
- 别忘了episode skill中需要用户确认的
- dropout比例 (默认推荐0.5). dropout功能的含义是在每一episode开始时，dropout掉一部分lora，以避免与之前的episode选到过于相似的lora。
- prompt数量 (默认下表，但需询问用户是否需要更多)
- 执行计划（简要说明即可）。记得告知（而非询问），这几个计划的timestep都是 lora_only 的

## reference

在寻找lora的时候，请一定要通过 get_loras.py 获取候选lora，这是lora库的唯一出口；不要直接阅读lora库原始md文件。

运行方式（在仓库根目录执行）：
```bash
uv run .agents/skills/lora-explore/scripts/get_loras.py --dropout=0.3
```

--dropout 必传，取值 [0,1)，表示随机丢弃的lora比例。
