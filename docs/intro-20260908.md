# ImageAutoPrompt

## 用对话来探索你的画风

帮你给 noobai / anima 模型写 danbooru tag、
并系统性试出最好用 prompt 的工具

2026-09-08

---

## 这是一个什么样的工具

**一句话：你负责提需求和打分，agent 负责写 prompt、跑图、记录历史。**

- **用聊天的方式使用**：全程通过 coding agent（ZCode / Claude Code 等）。
  你复制一句话给它，剩下的操作它全包了
- **探索方法已经写在仓库里**：怎么试画师、怎么试 lora，都有一套固定流程
  （叫 skill）。agent 会先问你几个关键问题，问清楚了才开工
- **直接用你自己的 ComfyUI 出图**：它不管 ComfyUI 本体的安装，
  也不改你的工作流，只是把写好的 prompt 塞进你的工作流里跑图

适合的人：已经有 ComfyUI、会（或打算）玩二次元模型的人。

---

## 为什么选 noobai 和 anima

它们是目前画二次元最好用的两个模型；出图工具方面，ComfyUI 是目前最好的。

| | noobai | anima |
|---|---|---|
| prompt 怎么被理解 | 用 CLIP。它像词袋模型：词都认识，但词和词的位置关系管不了 | 用 Qwen（语言模型）。prompt 读得更明白，你写什么它更听话 |
| 架构 | 成熟 | 更新、更先进 |
| 画师 tag | 理解得非常到位 | 不稳定：2 个画师最好，再多反而越差 |
| 建议怎么玩风格 | 靠**画师串** | 靠 **lora** |

一句话总结：**noobai 用画师串玩风格，anima 用 lora 玩风格。**

---

## 这么探索的原理是什么

不管是画师串还是 lora，它们都有两个好性质，让"探索"这件事是可行的：

- **可组合**：可以叠加多个（画师 2–5 个、lora 2–5 个），还能各调权重，
  组合空间非常大，好东西藏在里面
- **平滑性**：参数稍微变一点（换一个画师、调一点权重），
  画面通常也只变一点，不会一下子变成完全另一张图

因为画面是随参数**平滑变化**的，所以"你觉得这轮比上轮好"这个反馈是有意义的：
它说明参数挪动的方向是对的。

于是就可以像**二分查找**那样做实验：每一轮出一批图 → 你打分 →
根据反馈往好的方向收缩 → 一轮一轮逼近你最满意的风格。

不需要一次猜中答案，只需要每轮都比上轮更近一点——这就是整个工具的底气。

---

## 安装：一共 4 步

前提：你已经有 ComfyUI 和自己的工作流。这个仓库不负责装 ComfyUI。

| 步 | 做什么 | 说明 |
|---|---|---|
| 1 | 装运行环境（install-environment） | 用 uv 一条命令装出 `.venv`。很重的可选依赖放在单独分组里，不装也完全够用 |
| 2 | 填配置（setup-app-config） | 告诉工具你的 ComfyUI 在哪个地址 |
| 3 | 适配工作流（adapt-workflow） | 把你的工作流变成模板（插入占位符） |
| 4 | 启动 | 运行 `python server.py`。这是全程唯一要自己敲的命令 |

每一步都不用手动做，对 agent 说一句话就行：

```text
帮我使用 install-environment skill，安装环境
```

---

## 第 2 步：setup-app-config，告诉工具你的 ComfyUI 在哪

做这件事：复制模板 `app_config.example.yaml`，生成 `entropy/conf/app_config.yaml`。

- 真正要填的只有一个：你的 ComfyUI 地址（`comfyui_base_url`，
  本机默认 `http://127.0.0.1:8188`）
- 其余字段保持默认就行，每个字段模板里都有注释解释
- 配置是**热加载**的：改完马上生效，不用重启

什么时候会用到：首次安装，或者以后 ComfyUI 换了端口。

**给 agent 的指令**

```text
帮我使用 setup-app-config skill
```

---

## 第 3 步：adapt-workflow，把你的工作流变成模板

- 你在 ComfyUI 里把工作流「导出(API)」成 json，把文件交给 agent
- agent 复制一份放进 `entropy/conf/workflows/`（在副本上改，不动你的原文件），
  并在该放 prompt 的位置插入**占位符**
- 必填占位符两个：`entropy:positive`（正向提示词）、
  `entropy:output_image`（定位输出图片）；`entropy:negative` / `entropy:lora` 很少用
- 原理很朴素，就是**字符串替换**：采样器、模型、分辨率……
  工作流里的一切原样保留，工具只把 prompt 替换进去
- 创建 episode 时会把当时的工作流快照存进 episode.json，
  之后你再改工作流文件，不影响已经开始的 episode

> 理解这个仓库的钥匙：**它不接管你的工作流，只是把你的工作流模板化。**

**给 agent 的指令**

```text
我想加入新的 Workflow 到 entropy/conf/workflows，帮我使用 adapt-workflow
将我的 Workflow 进行修改，我将它下载下来了，文件地址是：___
```

---

## 第 4 步：启动

唯一手动命令：

```bash
# 可选：激活 python 环境
.venv/Scripts/activate

# 启动服务
python server.py
```

浏览器打开 `http://127.0.0.1:5000`。

这个网页就是你的操作台：管理 episode、看每轮出图结果、给图打分，都在这里完成。
（一会儿现场演示）

---

## episode：所有探索都装在 episode 里

一个 **episode**，就是"围绕同一个 prompt 反复改进"的一条完整历史。

- 一个 episode 里有很多个 **timestep**（理解成"一轮"就行）
- 每一轮的流程是：agent 准备一批 prompt → ComfyUI 批量出图 → 你给图打分
- 只需要写**正向** prompt。负向 prompt 你早就按自己的审美固定在工作流里了，
  agent 不用生成
- 不管探索画师、探索 lora 还是探索普通 tag，都是在某个 episode 里进行的
- episode 名字用 snake_case，比如 `blue_arche_uniform`

流程细节现场演示，看一遍就明白。

---

## 一轮一轮是怎么转起来的

1. 你提需求。agent 会先问清楚：episode 叫什么、用哪个模型、用哪个工作流、每轮出多少张
2. agent 写出这一轮的草稿。每一张图和上一轮比、改了什么，都写得清清楚楚
3. 跑图：草稿交给你的 ComfyUI，批量出图
4. 你在**网页端**给喜欢的图打高分
5. agent 把你的打分读回来，决定下一轮多试哪些方向、放弃哪些，然后回到第 2 步

转到你满意为止。最后 agent 会告诉你**最好的 3 个组合**。

---

## artist-explore：怎么探索画师

先说经验：只放一个画师，效果通常一般。把 **2 到 5 个画师**叠在一起（画师串），
才容易出好效果。好组合是**试出来的**，不是想出来的。

探索时最重要的纪律是**控制变量**：

- 探索期间**只改画师 tag**，其他 tag 一个都不动。
  这样图变好变坏，都只能是因为画师变了
- 画师 tag 的位置有讲究：放在人数、角色、系列这些 tag **后面**，
  不要放到整串 prompt 的最后
- **调权重是高级技巧**：先用无权重的组合把流程跑顺，之后再考虑微调，
  不要一上来就玩权重

**给 agent 的指令**

```text
在新 episode 中，帮我使用 artist-explore 探索 artist. prompt: 1girl, solo, ...
```

---

## noobai：一轮一轮筛的多轮漏斗

思路是从简单到复杂，每一轮淘汰掉不好的方向。
agent 根据你每一轮的打分，挑下一轮要试的组合。

| 阶段 | 试什么 | 每轮张数 |
|---|---|---|
| 0 | 先跑 `get_artists.py`，拿到一批候选画师 | — |
| 1 | 单画师，一个一个试 | 16 |
| 2 | 2 个画师混着试（不带权重） | 8 |
| 3 | 2–3 个画师，带权重 | 8 |
| 4–5 | 2–5 个画师，带权重（既要试新的，也要留下好的） | 8 |
| 收尾 | 告诉你**最好的 3 个画师串** | — |

---

## 候选画师从哪来：get_artists.py

```bash
python .agents/skills/artist-explore/scripts/get_artists.py --dropout=0.5
```

- `--dropout` 必须传，填 0 到 1 之间的小数，推荐 **0.5**
- dropout 的意思：每次开始新的探索时，**随机丢掉一部分画师不用**。
  这样每次探索见到的画师都不太一样，不会翻来覆去总用那几个老面孔
- 探索时用到的画师，**只能**从这个脚本给的候选里挑，
  不要自己去翻画师库原始文件

# lora 生态：三个工具环环相扣

**查名** artist-name-search
→ **搜索下载** civitai-lora-search
→ **私人 lora 库** `library/*.yaml`
→ **筛候选** `get_loras.py`
→ **探索** lora-explore

lora 不是凭空探索的：先把 lora 搜下来、记进你自己的库、给出评价，
探索的时候才有东西可选。

---

## artist-name-search：画师名字双向查询

痛点：同一个画师，danbooru 的 tag 和 pixiv 的昵称经常**完全对不上**
（有的还改过名）。你知道其中一个，很难猜到另一个。

- **反着查**：有 pixiv 主页，想知道 danbooru tag
  `pixiv.net/users/1960050` → `torino_aqua`
- **正着查**：知道 danbooru tag，想知道画师的标准名（日文名）和各平台主页
  `torino_aqua` → とりのあくあ、pixiv 链接……

为什么经常要用它：**civitai 上画师 lora 的名字，往往是画师的 pixiv 原名**。
所以搜 lora 之前，先用它把名字查清楚。

**给 agent 的指令**

```text
帮我使用 artist-name-search 找一找 pixiv的画师 (https://www.pixiv.net/users/1554775) 的danbooru tag是什么?
```

---

## civitai-lora-search：怎么才搜得全

```text
帮我使用 civitai-lora-search 搜索画师xxx的、适合于noobai的lora
```

搜不到，很多时候**不是没有，是搜法不对**。三条经验：

1. **用 pixiv 原名去搜，别用罗马字**
   搜「館田ダン」能搜到，搜 `kanda_dan` 搜不到。所以先用 artist-name-search 查出原名
2. **空格和下划线是两种写法，都要试**
   `torino aqua` / `torino_aqua` / `torino`，各搜一遍
3. **0 结果要存疑**
   civitai 的搜索偶尔会抽风。重要的画师，换个词再搜一次确认

结果会整理成一份清单（md 文件）：模型 id、版本、触发词、推荐权重、兼容性，
都列好，最后选哪个由你决定。

---

## 搜到之后：筛选、下载、入库

- **筛选**：看 version 里的 baseModel（训练底座）。illustrious 系的适配 noobai；
  作者在简介里明说基于什么训练的，最可信
- **下载**：你拍板了才下载。下载需要代理，遇到问题 agent 会带着你处理
- **入库**：下载完自动追加进 `library/{arch}_loras.yaml`，
  你的评价写在 `my_comment` 里：

```yaml
anima_fkey_1:
  url: https://civitai.red/models/2724437/?modelVersionId=3062077
  words: null          # 触发词
  weight: null         # 推荐权重
  my_comment: <5> 顶级 油画质感 色调冷
```

评价用固定记号写在开头（`<5>` 顶级、`<3+>` 有特色、`<3->` 有点问题、`<1>` 不用……）。
**这些记号就是下一步探索的筛选依据**——评价过的 lora 才有资格上场。

---

## lora-explore：和画师漏斗一个套路

| 阶段 | 试什么 | 每轮张数 |
|---|---|---|
| 0 | 先跑 `get_loras.py`，从你的 lora 库里筛出候选 | — |
| 1 | 单 lora，一个一个试 | 16 |
| 2 | 2 个 lora，带权重 | 8 |
| 3 | 2–3 个 lora，带权重 | 8 |
| 4–5 | 2–5 个 lora，带权重 | 8 |

- lora 的权重直接写在语法里：`<lora:xxx:1.0>`。从 1.0 开始试，最低降到 0.2
- 同样遵守**控制变量**：探索期间只改 lora，别的都不动
- 触发词放哪？agent 会先问你：你的工作流会自己替换触发词，
  还是需要手动写进 prompt

**给 agent 的指令**

```text
在新 episode 中，帮我使用 lora-explore 探索 lora. prompt: 1girl, solo, ...
```
