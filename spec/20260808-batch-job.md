# batch-job CLI 工具规格

> 日期: 2026-08-08 | 分支: hot | 状态: 阶段1完成，待确认进入阶段2

## 概述

一个通过 ComfyUI API 跑批量图片处理任务的命令行工具。输入一张图片，输出一张图片。单 job_folder 单 workflow。

---

## CLI 调用方式

```bash
uv run batch_job <job_folder> [port]
```

- `job_folder`: 任务目录路径（如 `./runs/batch_jobs/test_resize_pic`）
- `port`: ComfyUI 端口号，默认 `8188`
- 纯位置参数，不做 `--port` 之类的复杂解析
- base_url 固定为 `http://localhost:{port}`

---

## job_folder 结构

```
my_job/
├── job.json          # ComfyUI workflow 模板
├── a (1).jpg         # 输入图片
├── a (1).png
├── cat.webp
└── ...
```

### job.json

- ComfyUI workflow JSON，必须包含两个占位符（string replace）：
  - `"entropy_input_image"` → 替换为上传后的 LoadImage 引用值
  - `"entropy_output_image"` → 替换为 SaveImage 的 `filename_prefix`
- **两个占位符缺失任意一个，直接报错退出。**

### 输入图片识别

- 扫描 job_folder 下所有文件，扩展名匹配（大小写不敏感）：
  - `jpg, jpeg, png, webp, bmp, gif, tiff, tif, jfif, avif`
- **排除**文件名包含 `.batchjob.` 的文件（避免把之前的输出当做输入）

---

## 输出命名 & 跳过逻辑

- 输入 `my_photo.jpg` → 输出 `my_photo.jpg.batchjob.out.png`
- 输出强制 `.png`（ComfyUI SaveImage 固定输出 PNG）
- **跳过逻辑**：检查 `{原文件名}.batchjob.out.png` 是否已存在于 job_folder，存在则跳过该任务，不重复生产
- 汇总时单独统计"跳过"数量

## ComfyUI API 交互

### base_url

`http://localhost:{port}`（无 `/api` 前缀，无需 API Key）

### 1. 上传图片

```
POST {base_url}/upload/image
Content-Type: multipart/form-data
```

| 字段 | 值 | 说明 |
|---|---|---|
| `image` | 文件 | multipart 文件字段 |
| `overwrite` | `"true"` | 覆盖同名文件 |
| `type` | `"input"` | 持久化到 input 目录 |
| `subfolder` | `"batch_job"` | 统一子目录，便于用户手动清理 |

- 文件名使用 UUID 重命名（保留原始扩展名），避免冲突
- 返回格式：`{"name": "...", "subfolder": "batch_job", "type": "input"}`

### 2. 渲染 workflow

- 将 `job.json` 中的 `"entropy_input_image"` 字符串替换为 LoadImage 引用值
- LoadImage 引用值格式：`"batch_job/{uuid}.{ext}"`（包含 subfolder）
- 将 `"entropy_output_image"` 替换为 UUID 前缀 `"batchjob_out_{uuid}"`
- 替换方式：JSON string-level replace（与 `entropy/infra/comfy_api.py` 模式一致）

### 3. 提交 prompt

```
POST {base_url}/prompt
Body: {"prompt": <rendered workflow object>}
```

- 返回：`{"prompt_id": "..."}`

### 4. 轮询结果

```
GET {base_url}/history/{prompt_id}
```

- status_str 为 `"success"` → 解析 outputs，遍历找 `type == "output"` 的 image descriptor
- status_str 含 `"error"` / `"fail"` → 任务失败
- 超时时间：**300 秒**

### 5. 下载输出

```
GET {base_url}/view?filename={filename}&subfolder={subfolder}&type=output
```

- 返回图片二进制，写入 job_folder 中

---

## 并发

- `ThreadPoolExecutor(max_workers=5)`
- 单张图片：上传 → 提交 → 轮询 → 下载（同步链路）
- 5 条链路并行

---

## 错误处理

- **单张失败不阻塞其他任务**
- 每张图片完成/失败/跳过都实时打印到终端
- 所有任务结束后输出汇总：
  - ✅ 成功: N
  - ⏭️ 跳过: N
  - ❌ 失败: N（附失败列表）

---

## 设计约束

- 不读取 AppConfig，完全独立
- 使用 Python + uv 运行（依赖 requests, shortuuid 等，复用现有 pyproject.toml 的依赖）
- 代码风格参考仓库现有 `entropy/infra/comfy_api.py` 模式
- 日志直接打印到 stdout/stderr，不写日志文件
