# batch-v2-job CLI 工具规格

> 日期: 2026-08-15 | 状态: 达成共识，待实现

## 概述

一个通过 ComfyUI API 跑「文本参数笛卡尔积」批量生成任务的命令行工具。**不接收图片输入**，接收 input.yaml 声明的文本参数组合，对每个组合渲染 job.json 并生成一张图片。单 job_folder 单 workflow。

与 `batch_job.py`（图片版）不同：本工具输入是文本参数矩阵，输出是多个组合的 PNG。

---

## CLI 调用方式

```bash
uv run batch_v2_job.py <job_folder> <port>
```

- `job_folder`: 任务目录路径（如 `./runs/batch_jobs2/test_job_1`）
- `port`: ComfyUI 端口号（必填，不传报错）
- 纯位置参数，不做 `--port` 之类的复杂解析
- base_url 固定为 `http://localhost:{port}`

---

## job_folder 结构

```
my_job/
├── job.json          # ComfyUI workflow 模板
├── input.yaml        # 变量矩阵定义
└── output/           # 输出目录（自动创建）
    └── out_*.png
```

### job.json

- ComfyUI workflow JSON，必须包含占位符 `entropy_output_image`（对应 SaveImage 的 filename_prefix）
- **缺失 `entropy_output_image` → 直接报错退出。**

### input.yaml

定义变量的值矩阵。每个变量是一个 `{ 值key: 值 }` 映射，**变量顺序 = yaml 书写顺序**。

```yaml
vars:
  prompt_name:
    dress: |-
      1girl, solo, dress
    shirt: 1girl, solo, shirt

  lora:
    mignon1: <lora:noob_mignon>
    mignon_weak: <lora:noob_mignon:0.8>
```

---

## 笛卡尔积 & 执行顺序

- 以 input.yaml 的变量顺序做**嵌套 for**（外层先出现的变量）。
- 示例：`for prompt_name: [dress, shirt]` 嵌套 `for lora: [mignon1, mignon_weak]`，共 4 个组合。
- **执行顺序 = 文件名顺序 = input.yaml 变量顺序。** 这样相邻组合共享 prompt/lora 时可以利用 ComfyUI 缓存，局部性由用户自行通过 input.yaml 排列控制。

---

## 输出命名

- 输出到 `{job_folder}/output/out_*.png`
- 文件名：`out_{变量1名}_{值1key}_{变量2名}_{值2key}_...png`，按 input.yaml 变量顺序拼接。
- 示例：`out_prompt_name_dress_lora_mignon_weak.png`
- **值 key 即文件名片段**：合法性校验（非法字符 `/ \ : * ? " < > |`、控制字符、空白等），**非法直接报错退出，不做清洗改写。**

---

## 参数替换约定

1. **以 input.yaml 为准**，忽略 workflow 里其它 `${xxx}` 的语义。
2. **替换规则**：`${var}` → `json.dumps(值, ensure_ascii=False)` 后**剥掉最外层引号**的结果，注入到字符串内容里（模板中 `${var}` 必须被一对引号包着，如 `"${prompt_name}, masterpiece"`）。这样既还原字符串内部特殊字符的转义，又不破坏 JSON 语法结构。
3. `entropy_output_image` → 每个组合唯一的随机前缀（用于定位输出并下载）。

### 边界情况

- **场景 A**（job.json 出现 `${var}`，但 input.yaml 未定义）：**忽略 + 打印日志警告**。
- **场景 B**（input.yaml 定义了变量，但 job.json 完全没用到 `${var}`）：**直接失败**。
- `entropy_output_image` 缺失：**直接失败**。

---

## 跳过逻辑

- 组合对应的 `output/out_*.png` 已存在 → **跳过**该组合，不重复生成。
- 汇总时单独统计「跳过」数量。

---

## 并发

- `ThreadPoolExecutor(max_workers=2)`
- **有界提交窗口（errgroup 效果）**：大小为 2 的信号量 + 阻塞式按序提交。保证同时最多 2 个组合在飞，且按 input.yaml 顺序注入，保留局部性（与 `submit` 自身的调度顺序无关）。

---

## ComfyUI API 交互

与 `entropy/infra/comfy_api.py` 同思路：

1. **渲染 workflow**：替换 `${var}` + `entropy_output_image`（唯一前缀）
2. **提交**：`POST {base_url}/prompt`，body `{"prompt": <rendered>}`
3. **轮询**：`GET {base_url}/history/{prompt_id}`，`success` → 按唯一前缀匹配输出；`error`/`fail` → 失败
4. **下载**：`GET {base_url}/view?filename=...&subfolder=...&type=output`，写入 `output/out_*.png`

超时: 300 秒。

---

## 错误处理

- **单组合失败不中断**其余组合。
- 每个组合完成/失败/跳过实时打印到终端。
- 结束后汇总：
  - ✅ 成功: N
  - ⏭️ 跳过: N
  - ❌ 失败: N（附失败列表）
- 退出码：无失败 → 0，有失败 → 1。

---

## 设计约束

- 不读取 AppConfig，完全独立，单文件。
- Python + uv（依赖 requests，复用现有 pyproject.toml）。
- 代码风格参考 `entropy/infra/comfy_api.py` 与 `batch_job.py`。
- 日志直接打印到 stdout/stderr，不写日志文件。
